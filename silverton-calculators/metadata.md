# Metadata for the calculator pages

Set these in the CMS per page (K8 page settings / SEO fields). The preview
files in `preview/` carry exactly these values in their `<head>` — use them
as the reference for what the published pages should emit.

The CMS page name is rendered as the visible H1 and breadcrumb, so the page
name **is** the H1 — no H1 is included in the snippets (a commented-out
fallback H1 is provided inside each snippet in case a page type outputs no
heading).

## Post-publish verification checklist

- [ ] Each URL returns 200 and shows only its own calculator.
- [ ] View-source: self-referencing `<link rel="canonical">` and unique
      title/description on all four pages.
- [ ] Exactly one H1 per page, matching the page name.
- [ ] New URLs present in `sitemap.xml`; `robots.txt` requires no changes
      (nothing new is disallowed).
- [ ] Category/product links after each result resolve (spot-check a couple
      of product links for stock status).
- [ ] Mobile check at 390 × 844: no horizontal scrolling on any page.
- [ ] Structured data: run the URLs through Google's Rich Results Test —
      each specialist page has FAQPage + BreadcrumbList + WebApplication
      JSON-LD.
- [ ] GA4 Realtime: use each calculator and confirm the events arrive with
      the correct `calculator_type` (see tracking.md).
